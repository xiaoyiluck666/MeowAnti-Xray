# 1.5.0 Dual-loader Pressure Matrix

Status: in progress

## Purpose

Measure Fabric and NeoForge async rewrite behavior under the same Minecraft 26.2 workload before changing scheduling, allocation, or the default queue size.

## Controlled Method

- Use a clean `main` commit and JDK `25.0.2`.
- Use the same anti-xray config content, heap limit, view distance, simulation distance, world snapshot, and teleport route for both loaders.
- Start each queue-size sample from a fresh server process. Do not compare cumulative `/antixray profile` counters across multiple samples in one process.
- Run the default queue `16` smoke first: 2 clients for 25 seconds on each loader.
- Run the screening matrix with 8 clients for 90 seconds at queue sizes `0`, `16`, `32`, and `64`.
- Repeat the default and any candidate replacement three times before drawing a conclusion.
- Keep queue `16` unless both loaders show a repeatable benefit without worse heap headroom or tick health.

The checked-in collector writes raw logs and structured samples under the ignored `build/pressure-results/` directory:

```powershell
.\tools\capture-pressure-sample.ps1 -Loader fabric -Clients 2 -DurationSeconds 25 -ExpectedQueueSize 16
.\tools\capture-pressure-sample.ps1 -Loader neoforge -Clients 2 -DurationSeconds 25 -ExpectedQueueSize 16
```

For an official sample, do not pass `-AllowDirty`. The collector records the Git commit, target versions, JDK, CPU, memory, server command line, config checksum, queue/worker settings, runner metrics, and final RCON `status` / `config` / `profile` output.

### Collector validation

The collector itself was exercised on 2026-07-21 with a dirty development worktree and 10-second routes. These are tool-validation samples, not matrix evidence because the local Fabric and NeoForge config files had different hidden/replacement sets and the Fabric server process included an earlier failed collector attempt.

- Fabric: 2/2 play, 3624 chunks observed before the metric-window correction, 0 errors; RCON confirmed queue 16 and visible rewrite activity.
- NeoForge: 2/2 play, 2639 chunks observed before the metric-window correction, 0 errors; RCON reported rewriteTasks=2639 and syncFallbackRatio=31.1%.
- The first Fabric attempt exposed that Minecraft RCON requests must be queried sequentially; the runner now serializes `status`, `config`, and `profile` collection.
- Structured raw and envelope JSON files were successfully written under `build/pressure-results/` for both loaders.

## Acceptance

- All clients enter play and each sample reports zero runner errors.
- `rewriteTasks` is non-zero on both loaders.
- The configured queue is confirmed by RCON and the config checksum is recorded.
- In-flight work returns to zero and does not grow without bound.
- Heap and tick-health evidence accompanies any recommendation to change the default.
- Synchronous and asynchronous rewrite equivalence tests pass before scheduling code changes are released.
